# Workflow — от сценария к ролику

## A. Раскадровка

- Раздели сценарий на **биты**: одна мысль/действие = один бит. Бит = одна сцена в `SCENES` или фаза внутри сцены.
- Длина бита 2–4 с. Динамичный ролик для Reels — ближе к 2–2,7 с; спокойная объяснялка — 3–4 с.
- **Первый кадр уже интересный.** Никаких пустых заставок: с кадра 1 в кадре есть объект, движение или хук-текст.
- Каждый бит показывает **конкретное** утверждение сценария: «батарея садится» = шкала заряда уменьшается и что-то гаснет, а не абстрактные шестерёнки. Если сцена декоративная и ничего не сообщает — замени.
- Держи единство: одни и те же персонажи, цвета, предметы и направление света во всех сценах. Внешность не меняется без причины.
- Сценарий пользователя — закон: не переписывай его слова, не выкидывай пункты, не меняй факты. Если дана только идея — придумай короткий сюжет с началом, событием и развязкой (например: «кот видит кружку → толкает → БАМ!»).

## B. Тайминг внутри сцены

`t` — секунды от начала сцены. Каждое действие привязывай к окну: `prog(t, 0.2, 0.9)` даёт 0→1 c плавностью.
- Прорисовка контуров: 0,4–1,0 с на объект, с перекрытием (следующий начинается до конца предыдущего).
- Появление текста: 0,25–0,4 с, с подъёмом на 15–25 px.
- Главное событие сцены — в первой половине, вторая половина — «дышит» (лёгкое движение), чтобы зритель успел понять.
- Анимация без пауз: что-то всегда немного движется (волны, частицы, покачивание, дрейф камеры).

## C. Компоновка 9:16 (1080×1920)

- Верх 0–230 px и низ 1640–1920 px закрывает интерфейс Instagram — там ничего важного.
- Главный объект — в зоне y 520–1450, по центру или по правилу третей.
- Текст: заголовок 70–100 px, подпись 40–50 px, минимум 34 px. Ширина строки ≤ 86% кадра — используй `txtFit`.
- Читаемость текста поверх яркой картинки: тёмная подложка (`caption()` рисует её сам) или градиент сверху/снизу.
- Для 16:9 или 1:1 поменяй `CFG.W/H` и **перекомпонуй** сцены (не обрезай вертикальную).

## D. Правила кода (иначе запись и превью разойдутся)

- `draw(t)` первой строкой заливает весь кадр фоном.
- Запрещено внутри `draw`: `Math.random()`, `Date`, `performance.now()`, `requestAnimationFrame`, накопление состояния между кадрами. Случайность — только `rng(seed)` (создавай заново внутри draw или один раз заранее) и `hj(a,b,c)`.
- Любой кадр должен рисоваться с нуля в любом порядке (перемотка ползунком назад).
- Тяжёлые объекты (3D-сцены, текстуры, офскрин-холсты) создавай **один раз**: лениво в `if(!window.S){...}` или в функции `async function SETUP(){}` (движок вызывает её перед стартом). В `draw` только меняй позиции и рендери.
- Шрифты: `FONT` (Inter → системный), `Lora` для «рукописного» мела/книжного, `"Press Start 2P"` для пиксельных надписей (кириллицы в нём нет — по-русски используй FONT жирным). Шрифты грузятся из Google Fonts; если недоступны — подставится системный, это нормально.
- Общий слой поверх всех сцен (заголовок, прогресс, логотип-текст) — объяви `function OVERLAY(T,i,t){...}`; движок вызовет её после каждой сцены. T — общее время, i — номер сцены.
- 3D: `gl3d(scene, camera, 540, 960)` рисует three.js-сцену на весь холст (540×960 → растянется до 1080×1920, это быстро). Для пиксельного 3D: `gl3d(s,c,360,640,true)`. Хелперы: `roundedBox(w,h,d,r)` — скруглённый брусок; `project3D(vec, cam)` → экранные координаты для выносок `callout()`.
- three.js r128 (глобальный `THREE`): нет `RoundedBoxGeometry`, `RoomEnvironment`, `CapsuleGeometry` — используй `roundedBox`, сферы, цилиндры. Цвета задавай hex как есть (sRGB-кодирование выключено намеренно, цвета не выцветают).

## E. Проверка перед выдачей

Без Playwright (например, на Windows): `node scripts/preview-edge.mjs --html ролик.html --out ./out` — headless Edge/Chrome, Node 22+; печатает время кадра; `--frames 120,195` — выбранные кадры, `--mp4` — готовый MP4 через ffmpeg. Рабочие папки держи там, где хватает места на диске.

Если есть выполнение кода с Chromium/Playwright и ffmpeg (проверь `which ffmpeg`, `node -e "require('playwright')"`; не устанавливай ничего тяжёлого, если этого нет):
- `node scripts/render.mjs --html ролик.html --preview --out ./out` — сохранит кадры на 10/40/90% каждой сцены. Посмотри их: обрезка, слипшийся текст, пустые кадры, слишком тёмно/светло, стиль узнаётся сразу.
- `node scripts/render.mjs --html ролик.html --out ./out` — настоящий MP4 (H.264). Отдай его файлом **в дополнение** к HTML.

Если выполнения кода нет — пройди чек-лист глазами по коду:
1. Первый кадр не пустой, в нём уже есть объект или хук.
2. У каждой сцены фон заливается целиком.
3. Нет `Math.random`/`Date` в draw; нет переменных, которые копятся между кадрами.
4. Все `prog(t,a,b)` укладываются в длительность сцены `d`.
5. Текст не залезает в верхние 230 и нижние 280 px, длинные строки через `txtFit`.
6. Стиль соблюдён по всем пунктам «обязательно» из файла стиля — не просто перекрашен.
7. Для 3D раскомментирован three.js; тяжёлые объекты создаются один раз.

## F. Частые ошибки

- «Перекрашенный» стиль: та же картинка, другой цвет. Каждый стиль меняет **геометрию, линию, фактуру и движение**, а не палитру.
- Безликие шары вместо объектов. Делай узнаваемый силуэт: у катера — корпус, рубка, окна; у кота — уши, усы, хвост.
- Всё появляется одновременно. Раскладывай во времени.
- Огромные пустые зоны или, наоборот, всё мелкое. Главный объект занимает 40–70% ширины кадра.
- Текст на весь экран без подложки поверх пёстрой картинки.
